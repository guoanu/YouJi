# 日程 Todo 功能设计思路

> **状态**: 待选型
> **创建日期**: 2026-08-05

---

## 目标

在日历日程基础上，增加**任务清单 + 晚间总结**能力：
- 每天可以列出待办任务
- 晚上可以回顾每个任务的完成情况

---

## 方案一：Markdown 内嵌任务（轻量改动）

### 思路

不增加新的数据模型，直接在日程笔记中利用 Markdown checkbox 语法 + 底部总结模板。

### 新建日程时自动生成模板

```markdown
## 今日任务

- [ ] 任务一
- [ ] 任务二  
- [ ] 任务三

---

## 晚间总结

> 今日完成情况：_待填写_
>
> 未完成事项：_待填写_
>
> 明日计划：_待填写_
```

### 交互

```
┌─ 日历 ──────────────┐    ┌─ 编辑区 ──────────────┐
│ 点击 8月6日          │    │                       │
└─────────────────────┘    │ ## 今日任务            │
        │                  │ - [x] 完成Q3报告       │
        ▼                  │ - [ ] 开会讨论需求     │
                           │ - [ ] 更新文档         │
                           │                       │
                           │ ---                   │
                           │ ## 晚间总结           │
                           │ 完成2/3，需求讨论...   │
                           └───────────────────────┘
```

### 可统计的"完成率"

侧边栏日程分区标题旁显示今日完成率：

```
📅 工作日日程  2/5  ← 今日 3 个任务，完成 2 个
```

从 Markdown 内容中解析 `- [x]` / `- [ ]` 计数。

### 改动量

| 层级 | 内容 |
|------|------|
| 后端 | 新建日程时写入模板内容 |
| 前端 | 解析 checkbox 数量，标题显示完成率 |
| UI | 无新增组件 |

### 优点
- 改动极小，半天可完成
- 纯 Markdown，导出保留格式
- 不增加数据复杂度

### 缺点
- 任务无法跨日期追踪
- 统计依赖解析文本，不够健壮
- 无提醒/通知机制

## 方案二：独立任务对象 + 专用面板（功能完整）

### 思路

任务提升为独立数据实体，日程页面分为「任务面板」和「总结面板」两个视图。

### 数据模型

```typescript
interface ScheduleTask {
  id: string;
  date: string;        // "YYYY-MM-DD"
  title: string;
  completed: boolean;
  completedAt?: string;
  summary?: string;    // 晚间总结（可选）
  order: number;       // 排序
}
```

### 交互

```
┌─ 日历 ──────────────┐    ┌─ 编辑区 ────────────────────┐
│ 点击 8月6日          │    │                             │
└─────────────────────┘    │  📋 8月6日 任务    [总结模式] │
        │                  │  ┌─────────────────────────┐ │
        ▼                  │  │ ☑ 完成Q3报告            │ │
                           │  │ ☐ 开会讨论需求           │ │
                           │  │ ☐ 更新文档              │ │
                           │  │ ＋ 添加任务              │ │
                           │  └─────────────────────────┘ │
                           │                             │
                           │  ═══ 切换总结模式 ═══       │
                           │                             │
                           │  📝 晚间总结                │
                           │  ┌─────────────────────────┐ │
                           │  │ 完成 1/3                │ │
                           │  │ 需求讨论推迟到明天...    │ │
                           │  │ [保存总结]              │ │
                           │  └─────────────────────────┘ │
                           └─────────────────────────────┘
```

### 编辑区内嵌两个面板

| 模式 | 内容 |
|------|------|
| 任务模式（默认）| 可勾选的 checkbox 列表 + 添加按钮 + 拖拽排序 |
| 总结模式 | 完成率统计 + 每个任务的完成备注 + 总结合成文本框 |

两个模式通过顶部按钮切换（类似主窗口编辑/分栏/预览的切换）。

### 日历上的进度环

有任务的日期在日历上显示**迷你进度环**（替代琥珀色圆点）：

```
┌────┐  ┌────┐  ┌────┐
│ 4  │  │ 5  │  │ 6  │
│    │  │ ◔  │  │ ●  │  ← 半圆=部分完成  实心圆=全部完成
└────┘  └────┘  └────┘
```

### 改动量

| 层级 | 内容 |
|------|------|
| 后端 | 新增 `ScheduleTask` CRUD 命令（约 5 个） |
| 前端 | 新增任务面板组件、总结面板组件、进度环 |
| UI | 编辑器顶部新增模式切换按钮 |

### 优点
- 结构化数据，统计准确
- 丰富的交互（勾选、排序、总结）
- 日历上直观展示每日进度
- 未来可扩展：任务模板、重复任务、提醒

### 缺点
- 改动量大，约需 2-3 天
- 增加数据模型复杂度
- 导出时任务和笔记内容分离

---

## 对比

| 维度 | 方案一（MD模板） | 方案二（独立任务） |
|------|:---:|:---:|
| 开发工作量 | 低（半天） | 高（2-3天） |
| 任务勾选 | ✅ checkbox | ✅ 专用组件 |
| 拖拽排序 | ❌ | ✅ |
| 完成率统计 | 解析文本 | 直接查询 |
| 日历进度显示 | 数字 | 进度环 |
| 跨日期任务 | ❌ | 可扩展 |
| 导出保留 | ✅ | 需额外处理 |
| 未来扩展性 | 低 | 高 |

---

## 建议

- **如果追求快速上线**：选方案一，先验证使用频率
- **如果确定日程是核心功能**：选方案二，一步到位
